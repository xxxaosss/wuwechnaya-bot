# Журнал решений

Собрано из обсуждения в claude.ai на 2026-10-20. Дальше записи добавляются сюда же:
что решили и почему. Формат: заголовок, решение, причина, последствия.
Статусы: **принято**, **отложено**, **отклонено**.

## Архитектура и инфраструктура

### Модульный монолит вместо микросервисов — принято
Backend это один FastAPI-процесс с модулями `auth`, `inventory`, `worklog`. Отдельно только `bot-gateway`.
Причина: разработка в одиночку и 8 ГБ ОЗУ на Pi 4. Шесть сервисов дали бы накладные расходы
(контейнер, healthcheck и деплой на каждый) без пользы на тестовом контуре.
Последствие: границы модулей держим чёткими, чтобы выделить сервис позже.

### k3s на одной ноде Pi 4 — принято
Полный k8s и kind для Pi не подходят. Загрузка с USB SSD, Ubuntu Server 64-bit (ARM64).
Образы собираются только под `linux/arm64`.

### Одна PostgreSQL, несколько схем — принято
База `db_wu`, схемы `auth`, `inventory`, `worklog`, а не БД на сервис. Причина: память и простота бэкапов.
Миграций-инструмента нет, SQL выполняется вручную. Сначала миграция (nullable/default-колонки), потом деплой,
удаление колонок после деплоя.

### Брокер сообщений не внедряем — отложено
Событий (низкий остаток) пока мало, они возвращаются прямо в ответе API.
Если понадобится, берём NATS (около 20 МБ), а не RabbitMQ/Kafka.

### CI на GitHub Actions + GHCR, деплой вручную — принято
Сборка `linux/arm64` через QEMU/buildx, запуск по изменениям `backend/**` или `bot-gateway/**`.
Деплой: `kubectl rollout restart`. Тег `:latest` с `imagePullPolicy: Always`.
Недостаток: Argo CD не заметит новую сборку при неизменном манифесте. Цель: тег по SHA коммита, прописываемый CI.

### Argo CD — отложено
Argo CD на Pi установлен, перенос сервисов не выполнен (сервисы в namespace `default`).
План: namespace `barbershop`, секреты переносятся вручную, Postgres остаётся в `default`
(хост `postgres-postgresql.default.svc.cluster.local`), автосинхронизация включается после проверки.
Секреты в git не хранятся (`exclude` в Application для файлов `*secret*.yaml`).

### Секреты только в k8s Secrets — принято
`bot-secrets`, `db-secrets`, `ghcr-secret` создаются вручную через `kubectl`, в git их нет.
Хост БД в `DATABASE_URL` — имя сервиса, не `127.0.0.1`.

## Бот и доступ

### Telegram через long-polling, интерфейс на кнопках — принято
aiogram 3, FSM, inline-кнопки для выбора, reply-меню по роли вместо команд.
Выбор расходника: общий модуль `picker.py` с поиском по нескольким словам и страницами по 8 штук
(лимит Telegram — 100 кнопок). Роутер поиска подключается последним.

### Авторизация по telegram_id с одобрением админом — принято
Роли `pending` / `master` / `admin`. Пользователь пишет `/start`, админ подтверждает `/approve <id> <роль>`.
`ADMIN_TELEGRAM_ID` всегда считается админом. Проверка ролей только в боте.
Долг: у backend нет авторизации, наружу его открывать нельзя (до веб-панели нужен API-ключ).

## Предметная область

### Остаток хранится в базовой единице — принято
`inventory.consumables.unit` — `шт`, `мл` или `г`, `quantity` — всегда в этой единице.
`pack_size` — нетто одной пачки, штуки = `quantity / pack_size`. Так расход можно вводить и в пачках, и в мл/г,
а остаток остаётся единым. Пересчёты только через `backend/inventory/units.py`.
Количества в backend — `Decimal(str(x))`, float к Decimal не прибавляем.

### Нетто и тара — принято
Нетто — вес содержимого одной пачки, тара — вес пустой упаковки (только для учёта в `г`).
Тару задаёт администратор: числом либо «взвесил целую пачку» (вес минус нетто), либо колонкой импорта.
При смене учёта на `шт` нетто теряется, при уходе с `г` тара сбрасывается.

### Приход тремя способами — принято
Пачки (по умолчанию), граммы/мл содержимого, вес с упаковкой (нужна тара). Вес с упаковкой работает только в приходе.
Нетто можно поправить кнопкой при повторном приходе; вопрос про вес при каждом приходе не задаём.

### Режим «Инвентаризация» не нужен — отклонено
Остаток доводится приходом и списанием; вскрытые пачки закрывает приход «вес с упаковкой».
Вернёмся, если появится потребность в установке остатка «как есть» с отдельным типом записи.

### Цен расходников в системе нет — принято
Хранятся позиции, штуки, объём/вес. Убраны цена, себестоимость, поставщик, номер документа.
Цена услуги и стоимость выполненной работы остаются (для отчётов).

### Импорт списков из накладных через CSV — принято
Только администратор, кнопка «📥 Импорт накладной». Формат: `Название;Штук;Объём;Ед;Вес, г;Тара, г`, разделитель `;`, UTF-8.
Позиции ищутся по названию без учёта регистра, новые создаются. `Штук = 0` допустимо: позиция только заводится.
Колонка «Вес, г» переводит позицию в граммы (число пачек сохраняется).
Защиты от повторной загрузки нет: вместо неё в превью строка «было → станет».
Названия сокращены (до 100 символов, без артикулов и английских дублей), дубли между накладными убраны.

### Проведение работы одним диалогом — принято
Услуга → расходники (мультивыбор) → количества → клиент → стоимость. Проверка остатков до любых изменений,
списание и запись работы одной транзакцией. Расход можно вводить в пачках или в мл/г.

### Порог «заканчивается» в пачках — принято
Задаётся администратором в «✏️ Расходник». Уведомления пока не реализованы:
предупреждение показывается только в ответе мастеру и в списке остатков.

## Сеть

### Обход Telegram через wlan0 — принято (причина не найдена)
С Pi через туннель `awg0` до 30% соединений к `api.telegram.org` рвались (`Connection reset by peer`),
а с Mac по тому же маршруту всё работало, и напрямую с Pi через LAN тоже.
Не подтвердились: MTU (1280 и 1376 одинаково, значения на роутере, Pi и Mac совпадают), DNS, маршрут роутера.
Решение: systemd-юнит `telegram-direct-route` добавляет маршрут `149.154.160.0/20` через `192.168.1.1` dev `wlan0`.
Если бот снова рвёт соединение, проверить `ip route get 149.154.166.110` (должен быть `wlan0`).
Если Pi подключат кабелем, в юните заменить `wlan0`.

## Инциденты и уроки

- OOMKilled при лимите 128Mi у бота, сейчас 512Mi.
- Два экземпляра бота одновременно дают TelegramConflictError 409 и CPU в потолок, после рестарта проверять, что остался один под.
- `Decimal + float` падает, вся арифметика в Decimal.
- Относительные импорты в backend ломались при запуске из `backend/`, импорты абсолютные.
- `rollout restart` без дождавшейся сборки поднимает старый образ.
- Пароль БД и токен бота светились в переписке и в опубликованной странице: после переезда сменить.
